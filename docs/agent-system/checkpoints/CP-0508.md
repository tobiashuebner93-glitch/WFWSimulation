## Implementierung und Grenzen

Der Planer liest die im angenommenen Angebot festgeschriebenen Bedingungen und Markt-Fertigungsanforderungen. Für jede angefragte Fähigkeit muss ein passendes Profil vorhanden sein und durch eine Person mit erforderlichen Skillstufen/Qualifikationen sowie einem passenden Betriebsmittel erfüllt werden. Er reserviert Arbeitszeit auf verfügbaren Werktagen bis zum angenommenen Liefertermin, zerlegt längere Arbeit in Tagesblöcke, verknüpft Schritte als Vorgängerkette und setzt profilbasierten Materialbedarf am letzten Block an. Die bestehende `planV3RunWorkOrder`/Produktlebenszyklusprüfung validiert den Gesamtplan. Eine fehlende Voraussetzung stoppt die Planung, ohne den Run zu verändern.

Die Arbeitsdauer folgt vorläufig der Szenarioannahme „ein Kapazitätspunkt = eine modellierte Arbeitsstunde“. Für Material wird die erste passende Archetyp-Rezeptur pro vereinbarter Angebotsmengeneinheit verwendet; pro Mengeneinheit wird eine Lagerkapazitätseinheit angesetzt. Das sind synthetische Spielwerte, keine real gemessenen Zeit-/Material- oder Qualitätsdaten. Der Planer erstellt keinen Qualitätsforecast und nimmt keinen direkten Nutzerzugriff auf diese technischen Parameter an. `sets` und `lots` benutzen dieselbe ausdrücklich synthetische Einheitenskalierung; das ist noch fachlich zu prüfen.
