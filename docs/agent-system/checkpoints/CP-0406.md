## Browsernachweis

Ein frischer Browser-Tab lud den aktuellen hashgebundenen `run.js`-/`run.css`-Stand. Die Datei `run.js` hatte beim Check SHA-256 `c467106116422fb711f5f164a42af2bcaeb8ccabad54fb32160ed040338314da`, passend zum Token in `run.html`. Der V3-UPSWING-Lauf `V3-RUN-SYNTH-01`, Seed `seed-v3-001`, Zeitraum 04.01.2027–29.01.2027 wurde mit explizit leeren Anfangsressourcen gestartet; der erste Simulationstag wurde geöffnet.

Im offenen Kundenanfrageformular war `Unadjusted · eingegebene Planwerte` sichtbar vorausgewählt. Die Opt-in-Auswahl und Erläuterungen waren lesbar; sie benennen Plan-/Szenariowerte, Jan-2027-Basis, kategorisierte direkte Kosten, Procurement als gemeinsamen Material-/Logistikindex, Wage-Index für direkte Arbeit, unverändertes `other`, keinen BICI-Kaskadeneffekt und unverändertes `R`.

Nach Auswahl von `Mit L4-Planindizes rechnen` und gültigen Testangaben für Preis, Kostenkennungen, direkte Materialkosten sowie BAB-Pool/Treiber, aber ohne verfügbaren ProcurementPlanIndex, zeigte die Runtime `Angebotskalkulation ausstehend: Es wird genau ein procurementPlanIndex für 2027-01 benötigt.` Es entstand kein abgegebenes Angebot. Damit ist für diesen Browserpfad kein stiller Basisindex und kein stiller unadjusted-Fallback sichtbar.

Danach wurde derselbe Testdatensatz explizit auf `Unadjusted` zurückgestellt. Die Angebotsabgabe gelang; die UI zeigte rechnerischen DB I 90,00 €, Ergebnis nach BAB 89,90 € und „Kundenentscheidung steht aus“. Der Run blieb im separaten flüchtigen Browser-Tab.
