# Agent Preflight – WFWSimulation

Vor jeder Bearbeitung:

1. AGENTS.md lesen.
2. agent-structure.md lesen.
3. goals.md lesen.
4. aktuelles Master Goal feststellen.
5. aktuelles Second-Level Goal feststellen.
6. ticket-board.md lesen.
7. Tickets auf aktuelles Master-/Second-Level Goal filtern.
8. abgeschlossene Second-Level Goals und deren Tickets aus dem aktiven Kontext ausschließen.
9. collaboration-state.md lesen.
10. relevante Architektur-/Fachdokumente lesen.
11. decision-log.md auf relevante Entscheidungen prüfen.
12. Repository-Stand prüfen.
13. Änderungen anderer Agenten prüfen.
14. offene Entscheidungen und Blocker prüfen.
15. Erst danach mit der Arbeit beginnen.

## Checkpoint-Regel

Maximal 3 eigenständige Arbeiten ohne dauerhafte Dokumentation.

Die vierte Arbeit darf erst nach einem Checkpoint beginnen.

Sofortiger Checkpoint bei:

- Entscheidung
- Architekturänderung
- wesentlicher Erkenntnis
- Blocker
- neuer Abhängigkeit
- Goaländerung
- Ticketänderung
- schwer rekonstruierbarem Arbeitsergebnis

Checkpoints müssen historisch nachvollziehbar bleiben.

Ein Ticket darf IN_PROGRESS bleiben und mehrere Checkpoints besitzen.
